## [v0.1.0] - 2026-09-08 ([`c083052`](https://github.com/plexusone/systemspec-crypto/commit/c083052))

### Highlights

- Initial release of systemspec-crypto: a Go-first, machine-readable IR describing the cryptography a system uses as facts and evidence, never prose. Implementations separate `capabilities` (what they can do) from `usedCapabilities` (what the system does with them), and every claim carries a verification state (discovered → inferred → review-required → verified → attested).
- A `cryptospec` CLI validates a spec against structural rules and reports a human-readable summary; the same subcommands mount under a family aggregate CLI via `NewRootCommand`/`NewCommand`.
- Dogfooded end to end on the public plexusone/omniagent platform (Argon2id passwords, SHA-256 token hashing, ECDSA/RSA JWT verification, crypto/rand CSPRNG), and exported to a CycloneDX 1.6 CBOM.

### Added

- Core IR types: Spec envelope with format-semver `specVersion`, system identity, and scope ([`cbcacde`](https://github.com/plexusone/systemspec-crypto/commit/cbcacde))
- Shared primitives: Lifecycle vocabulary, Provenance, and type-prefixed ID conventions ([`777b80d`](https://github.com/plexusone/systemspec-crypto/commit/777b80d))
- Implementation, Algorithm, and Use models — Implementation separates capabilities from usedCapabilities (the anti-hallucination control); Use ties an algorithm to a purpose, component, configuration, locations, and evidence ([`f0c9d0c`](https://github.com/plexusone/systemspec-crypto/commit/f0c9d0c))
- Evidence, Claim, and the Verification state machine; claims are the single verification surface, covering inventory objects by reference ([`0de298c`](https://github.com/plexusone/systemspec-crypto/commit/0de298c))
- Go-first JSON Schema generation pipeline (invopop/jsonschema), embedded via go:embed and linted clean by schemakit for static-type friendliness ([`a358493`](https://github.com/plexusone/systemspec-crypto/commit/a358493))
- Structural validation rules engine: referential integrity, capability containment, controlled-vocabulary conformance, ID conventions and uniqueness, and evidence requirements on verified/attested claims ([`475b2a2`](https://github.com/plexusone/systemspec-crypto/commit/475b2a2))
- `Parse` loader that rejects unknown fields ([`d7e71a5`](https://github.com/plexusone/systemspec-crypto/commit/d7e71a5))
- `cryptospec validate` command with text and JSON output and error-gated exit codes ([`2571c1a`](https://github.com/plexusone/systemspec-crypto/commit/2571c1a))
- `cryptospec report` command: internal summary of implementations, algorithms, uses grouped by purpose, and claims by verification state ([`70caa78`](https://github.com/plexusone/systemspec-crypto/commit/70caa78))
- CycloneDX CBOM export bridge and `cryptospec cbom export` command; the lossy projection reports the facts CBOM cannot carry ([`e1d8d36`](https://github.com/plexusone/systemspec-crypto/commit/e1d8d36))
