## [v0.1.0] - 2026-09-08 ([`7e512e8`](https://github.com/plexusone/systemspec-crypto/commit/7e512e8))

### Highlights

- Initial release of systemspec-crypto: a Go-first, machine-readable IR describing the cryptography a system uses as facts and evidence, never prose. Implementations separate `capabilities` (what they can do) from `usedCapabilities` (what the system does with them), and every claim carries a verification state (discovered → inferred → review-required → verified → attested).
- A `cryptospec` CLI validates a spec against structural rules and reports a human-readable summary; the same subcommands mount under a family aggregate CLI via `NewRootCommand`/`NewCommand`.
- Dogfooded end to end on the public plexusone/omniagent platform (Argon2id passwords, SHA-256 token hashing, ECDSA/RSA JWT verification, crypto/rand CSPRNG), and exported to a CycloneDX 1.6 CBOM.

### Added

- Core IR types: Spec envelope with format-semver `specVersion`, system identity, and scope ([`e65dc0c`](https://github.com/plexusone/systemspec-crypto/commit/e65dc0c))
- Shared primitives: Lifecycle vocabulary, Provenance, and type-prefixed ID conventions ([`fb0d854`](https://github.com/plexusone/systemspec-crypto/commit/fb0d854))
- Implementation, Algorithm, and Use models — Implementation separates capabilities from usedCapabilities (the anti-hallucination control); Use ties an algorithm to a purpose, component, configuration, locations, and evidence ([`aaf2a5d`](https://github.com/plexusone/systemspec-crypto/commit/aaf2a5d))
- Evidence, Claim, and the Verification state machine; claims are the single verification surface, covering inventory objects by reference ([`5611194`](https://github.com/plexusone/systemspec-crypto/commit/5611194))
- Go-first JSON Schema generation pipeline (invopop/jsonschema), embedded via go:embed and linted clean by schemakit for static-type friendliness ([`e92fec0`](https://github.com/plexusone/systemspec-crypto/commit/e92fec0))
- Structural validation rules engine: referential integrity, capability containment, controlled-vocabulary conformance, ID conventions and uniqueness, and evidence requirements on verified/attested claims ([`fea4ad0`](https://github.com/plexusone/systemspec-crypto/commit/fea4ad0))
- `Parse` loader that rejects unknown fields ([`0fcaf11`](https://github.com/plexusone/systemspec-crypto/commit/0fcaf11))
- `cryptospec validate` command with text and JSON output and error-gated exit codes ([`3ce8a4c`](https://github.com/plexusone/systemspec-crypto/commit/3ce8a4c))
- `cryptospec report` command: internal summary of implementations, algorithms, uses grouped by purpose, and claims by verification state ([`9d0276f`](https://github.com/plexusone/systemspec-crypto/commit/9d0276f))
- CycloneDX CBOM export bridge and `cryptospec cbom export` command; the lossy projection reports the facts CBOM cannot carry ([`174ca4f`](https://github.com/plexusone/systemspec-crypto/commit/174ca4f))
